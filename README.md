# EEG N170 Pegasus Workflow

A [Pegasus WMS](https://pegasus.isi.edu/) workflow for a group-level N170 analysis
of the OpenNeuro dataset **ds007096** (PURSUE N170 Face Perception, CC0).

**Provenance.** This workflow was scaffolded, debugged, and executed entirely
inside Pegasus AI Studio by an open-weight model (Kimi K2.6) driving the OpenCode
CLI against Studio's projected knowledge base (see `cc-usage-log.md`). The run of
record on the Studio HTCondor pool completed 127 of 127 jobs (97 tasks, 24
subjects) with zero failures and zero retries in 5m40s of workflow wall time, per
`pegasus-statistics`. The staged outputs of that run are kept in `output/`. The
run directory itself, the built `.sif` images, and the `pydeps.tar.gz` bundle
remain on the Studio container.

## Pipeline Overview

Per-subject fan-out followed by a single fan-in group stage:

```
fetch_subject ──> preprocess ──> epoch ──> average
                     │                            \
                     │                             \
                     └─────────────────────────────────> group_contrast
```

| Step | Description |
|------|-------------|
| **fetch_subject** | Downloads `.set`, `channels.tsv`, and `events.tsv` from OpenNeuro S3 |
| **preprocess** | Loads EEGLAB data, applies standard_1020 montage, filters (0.1–40 Hz), notch 60 Hz, average reference |
| **epoch** | Creates face (values 1–40) and car (values 41–80) epochs from –200 to +800 ms |
| **average** | Computes evoked responses per condition; outputs `erp_<ID>.fif` + `erp_<ID>.png` |
| **group_contrast** | Grand averages, face–car difference wave, N170 peak metrics, summary PDF |

## Directory Structure

```
eeg-workflow/
├── workflow_generator.py      # Pegasus workflow generator
├── bin/
│   ├── fetch_subject.py       # Download subject data from OpenNeuro
│   ├── preprocess.py          # Filter, montage, re-reference
│   ├── epoch.py               # Build face/car epochs
│   ├── average.py             # Subject-level evoked response + plot
│   └── group_contrast.py      # Group-level contrast + report
├── Apptainer/
│   ├── EEG_Container.def        # Container definition (Python 3.12)
│   └── EEG_Container_py313.def  # Container definition (Python 3.13, used for pydeps)
├── output/                    # Staged outputs of the 24-subject run of record
├── run_manual.sh              # Local test script
└── README.md
```

Built artifacts are not checked in. The `.sif` images and the
`pydeps.tar.gz` dependency bundle are rebuilt from the definitions above
(Setup step 1), and the workflow YAML plus the site, transformation, and
replica catalogs are regenerated by `workflow_generator.py`, which
derives all paths from its own location.

## Prerequisites

- [Pegasus WMS](https://pegasus.isi.edu/) >= 5.0
- [HTCondor](https://htcondor.org/) >= 10.2
- Python 3.8+ with `requests` and `pandas` (for the generator)

## Setup

### 1. Build the portable Python dependency bundle

The workflow transfers a self-contained Python package bundle (`pydeps.tar.gz`) to
worker nodes so that MNE-Python and its dependencies are available without requiring
a container runtime on the workers.

**The bundle's Python minor version must match the worker nodes' `python3`.**
Compiled extensions (numpy, scipy) built for one minor version fail with
`ModuleNotFoundError` on another. Check the workers first:

```bash
condor_ssh_to_job <any-job-id> python3 --version   # or ssh to a worker
```

The workers this workflow was verified on run Python 3.13, hence the `py313`
container definition below. For workers on a different version, edit the
`From:` line of the definition to the matching `python:3.X-slim` image (a 3.12
definition is already provided as `EEG_Container.def`). The extraction command
below locates the site-packages directory itself, so it works unchanged for any
version:

```bash
cd eeg-workflow
apptainer build Apptainer/EEG_Container_py313.sif Apptainer/EEG_Container_py313.def
apptainer exec Apptainer/EEG_Container_py313.sif sh -c \
    'tar czf pydeps.tar.gz -C "$(python3 -c "import site; print(site.getsitepackages()[0])")" .'
```

(The bundle can also be created from any Python environment of the matching
version with the required packages installed, using the same
`site.getsitepackages()` trick to find the directory to bundle.)

If `pydeps.tar.gz` is absent when the generator runs, the generator prints a
warning and the jobs fall back to the worker's system Python, which must then
already provide `mne`, `pandas`, `matplotlib`, `pymatreader`, and `h5py`.

### 2. Test Locally (Optional)

```bash
./run_manual.sh
```

This downloads one subject, runs all per-subject steps, simulates a second subject,
and tests the group contrast wrapper. It runs the `bin/` tools directly, so the
local Python needs the full analysis stack (`mne`, `pandas`, `matplotlib`,
`pymatreader`, `h5py`, `requests`), or run it inside the container built in step 1.

## Usage

### Generate the Workflow

```bash
python3 workflow_generator.py --num-subjects 24 --output workflow.yml
```

To process an explicit list of subjects:

```bash
python3 workflow_generator.py --subject-ids 1001 1002 1003 --num-subjects 3 --output workflow.yml
```

### CLI Options

| Option | Default | Description |
|--------|---------|-------------|
| `--num-subjects` | `24` | Number of subjects to process from the cohort |
| `--subject-ids` | *(from `participants.tsv`)* | Override with explicit IDs |
| `--min-subjects` | `max(2, num_subjects)` | Minimum subjects required for group stage (must be ≥ 2) |
| `-e`, `--execution-site-name` | `condorpool` | HTCondor execution site name |
| `-s`, `--skip-sites-catalog` | `false` | Skip writing the site catalog |
| `-o`, `--output` | `workflow.yml` | Output workflow file |

### Submit the Workflow

```bash
pegasus-plan --submit -s condorpool -o local workflow.yml
```

### Monitor

```bash
pegasus-status <run-directory>
pegasus-statistics <run-directory>
```

## Outputs

Final outputs are staged to the `output/` directory:

| Output | Description |
|--------|-------------|
| `erp_<ID>.fif` | Per-subject evoked responses (Face + Car) |
| `erp_<ID>.png` | Per-subject ERP plot |
| `n170_summary.pdf` | Group grand averages and difference wave with peak |
| `metrics.json` | Peak latency (ms), peak amplitude (µV), and subject count |

## Resource Requirements

| Step | Memory | Cores |
|------|--------|-------|
| fetch_subject | 1 GB | 1 |
| preprocess | 4 GB | 2 |
| epoch | 4 GB | 2 |
| average | 2 GB | 1 |
| group_contrast | 4 GB | 2 |

## Notes

- Data is fetched at runtime from `https://s3.amazonaws.com/openneuro.org/ds007096/sub-<ID>/eeg/...`.
- No credentials are required (CC0 public dataset).
- If fewer subjects than `--min-subjects` are present at the group stage, the `group_contrast` job exits non-zero and lists the missing subject IDs.
